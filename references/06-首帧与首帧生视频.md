# 06 首帧与首帧生视频（craft = i2v）

> 管：首帧档的镜头组怎么判走法、首帧图提示词（单图 / 宫格）、首帧生视频提示词（Omni / Wan3.0）怎么写。
> 不管：要不要进首帧档（见 04 工艺与模型判定）、通用镜头设计（03）、参考生视频写法（05）。
> 出图只交付提示词，EV 自己去 Gemini 跑；本 Skill 不调任何生图/生视频接口，也不切宫格。
> **语言（EV 11-07 已裁定）：一律中文**——首帧生图（Gemini 单图 / 宫格，Gemini 多语言）、Wan3.0、Omni 都写中文。唯一例外：Omni 官方只写“English is fully supported, other languages have not been evaluated”，所以 Omni 组正文仍用中文，另附 `promptEn` 英文备用版（以 `meta.stylePrefixEn` 开头），中文效果不好时换它。

## 一、首帧档的走法与判定

**前提：首帧档只放不说话的镜头**（空镜、静态物件特写、没有群演或群演不说话的切镜段落）。有人开口就不属于首帧档，回到 04 改派（群演有台词 → H3，主角对白 → SD2.0）。原因：首帧和参考素材互斥，首帧模式锁不了声音（Q60/Q61 官方）。

### 1.1 四种走法

| # | 什么镜头 | 首帧图 | 生视频 | 一行 = | frame.mode | dur |
|---|---|---|---|---|---|---|
| A | 简单空镜、静态物件特写，**不切镜** | Gemini 单张 | Omni，单镜头 | 一个镜头 | `single` | 10 |
| B | **要切镜**的空镜（没有群演或群演不说话），总长 ≤10 秒 | Gemini 单张（= 第一镜的画面） | Omni **一次出多镜**，`[0-3s]` 时间码 | 一个镜头组（2–4 镜） | `single` | 10 |
| C | 同 B，但**每镜构图必须先定死**，或**总长超 10 秒**（备选） | Gemini 宫格（2×2） | Omni，**逐格**单镜头生成 | 一格一行 | `grid` + `cell` | 10 |
| D | **长空镜**：一个连续镜头超过 10 秒 | Gemini 单张 | Wan3.0，单镜头 | 一个镜头 | `single` | 11–30 |

### 1.2 判定顺序

1. 有人说话？→ 是：不进首帧档。
2. 是不是一个连续镜头、超过 10 秒？→ 是：**D（Wan3.0）**。
3. 要不要切镜？→ 不要：**A**。
4. 要切镜：总长 ≤10 秒、构图不要求逐镜定死 → **B（默认）**；总长超 10 秒，或导演明确要每镜构图先锁死 → **C（宫格）**。

### 1.3 硬规则

- **Omni 单次固定 10 秒**，`dur` 一律填 10（EV 定）；剪辑取多少是剪辑师的事，表里不加“取用时长”。
- **Omni 只有 16:9 / 9:16**：成片画幅是这两种之一就直接用；其他画幅（4:3、1:1、2.39:1）的空镜一律按 16:9 出、后期裁，**不为画幅换模型**（EV 定）。首帧图画幅必须和 Omni 出片画幅一致，否则会被裁边（Q61 第三方实测）。
- **宫格只为切镜后的一致性，不为切而切。** 能 B 就不 C。
- 宫格一律 **2×2**（左上/右上/左下/右下），≤4 镜；超过 4 镜拆两张宫格，共用同一组参考图。
- 走 C 时，一张宫格出几行，几行的 `frame.prompt` **逐字相同**，只有 `frame.cell` 不同；切图交给用户，表里只写取哪一格。
- 走 B 时，首帧图 = 第一镜（`[0-Xs]` 那一段）的画面；后面几镜的画面由 Omni 自己生成。
- 编号只在表里用，**提示词里不出现场号、组号、格号**。

## 二、首帧生图提示词（单图）

### 2.1 挂不挂资产图（先定这个）

首帧图里的场景、人物、道具要和副导演资产盘点（ad-asset-bible）对得上。Gemini 网页能上传参考图，所以：

| 情况 | 做法 |
|---|---|
| 画面里的地点**有场景资产成图**（主 tag 或变体 tag） | **挂这张图做参考生图**。提示词开头一句交代“用附图当地点参考，保留它的路面/墙/参照物”，然后只写**这一镜的机位、光、空气**，不再重述资产 brief 的全部内容 |
| 有已建档的角色·服装、道具入画（不说话） | 一并挂上对应成图；提示词里只写他在画面里的位置和姿态，不写外观（和视频提示词“挂了图不写外观”同一条规矩） |
| 机位和资产主视角差得很远（反打、俯拍） | 仍挂图，但要把**物体新位置逐件写明**（Lira：NBP 换视角必须讲清摆位，否则几何乱）；资产里本来有机位变体就挂变体 |
| 资产还没出图 | 不挂图，按资产 brief 的内容改写进提示词（地点是什么、一两处痕迹、参照物），**参照物必须写进画面** |
| 画面里有**未建档**的东西（一次性道具、车辆外观、群演） | 文字泛写，同时在 `unbuilt` 里如实列出 |

- 参考图**不要用多格合图**（四视图、宫格）当参考：模型会把输出也画成宫格（Q60 第三方）。
- 用到的资产 tag 写进 `assets`；首帧挂给 Gemini 的图写进 `frame.refs`（契约已有，build.mjs 会核 tag）。

### 2.2 模板（中文；结构沿用 Lira 地点模板）

```
[挂图时：以附图作为地点参考：保留同样的<资产里的结构>，以及<参照物>。]
[构图词：竖构图 / 横构图。]
[机位锚点：景别 + 角度 + 摄影机在哪、朝哪，参照物在画面哪个位置。]
[地点身份：年代、城市、室内外、昼夜。]
[这一镜要看到的主要元素；未建档物体泛写。]
[光：光源是什么、在哪个方向、什么色温感。]
[空气层：一种空气 + 来源 + 在哪一层 + 光在里面怎么散。]
[远景衰减：只有前景有细节，中景以后化成柔和、扁平、偏浅的形块。]
[空镜写成场景属性：街上空空荡荡，安静。]
[调色块：褪色、低饱和……一个暖色点缀……低对比，黑位略微抬起。]
[技术块一句：写实摄影，ARRI Alexa LF，35mm 柯达 Vision3 250D 胶片颗粒，电影剧照质感。]
```

### 2.3 要点

- **跟随美术方案**：风格、年代、色调从 `meta.stylePrefix(En)` 来，**不强制写实**——美术方案是动画/插画就照美术方案写，技术块随之替换。
- **约 150–300 字**，自然语句，不堆关键词（Lira #1 #2 的中文化；原规定 80–150 个英文词）。
- **只写想要的**：Gemini 生图没有负面参数，“不要人”写成“街上空空荡荡”（Lira #3）。
- **地点不写景深/光圈**，远处的柔要靠空气层和远景衰减（Lira #5 #11）；不用“体积光”“史诗感”“超锐利”“清晰锐利”。
- **光写清光源位置即可**，不逐处写透光、高光（Gemini 高思考档会按光路自己纠正；写错光路反而造出错误高光——EV 10-26/10-28 实测）。
- **颗粒、细调色不靠提示词**：只留一句颗粒当风格锚点，颗粒和最终调色放后期（达芬奇），而且要加在成片视频上——首帧颗粒过图生视频会被重新生成（EV 10-14/10-26 实测）。
- 冷色写准：说“冷蓝灰”“钢蓝”，别写“青绿”（teal-green 会偏绿，EV 实测）。
- 暖色最容易过饱和：暖色物体写成“暗哑的”“蒙尘的”。
- 画面里有字（招牌、站牌）就写出确切文字；不需要可读文字就别提。不写真人名、品牌名。
- 首帧 = 视频第一帧：构图要给运动留余地（要推镜就别把主体塞满，要车驶来就让路的远端留空）。

## 三、宫格提示词（备选，走法 C）

### 3.1 沿用《镜语师》的部分

- **固定布局**：左上 P1 / 右上 P2 / 左下 P3 / 右下 P4，阅读顺序左→右、上→下；横纵中线平分四个等大格。
- **无缝、无边框**：写“无缝的 2×2 分镜宫格，一体画面，没有边框”；不要外框、白边、辅助线、网格线、格内编号或文字。
- **单格内不分屏**：每格是一个纯粹的电影镜头。
- **相邻格景别跳开**：P1→P4 景别要有明显跨度（远景→特写→中景→全景这类），不要连续相邻景别。
- **动作接戏、空间统一**：四格是同一段连续时间里的同一个空间，不是四张独立插图。
- **挂了参考图的主体不写外观**，用“附图里的地点”指代。
- 回忆段落：加“怀旧复古滤镜，老照片质感，轻微暗角，褪色，胶片颗粒”（镜语师原有，原文英文）。

### 3.2 去掉 / 改掉的部分

| 镜语师原规则 | 本 Skill |
|---|---|
| 强制写实 | 跟随美术方案（`meta.stylePrefix(En)`） |
| 强制 9:16 竖版 | 宫格总画幅 = 首帧要的画幅（= Omni 出片画幅：9:16 或 16:9）。行列相同，每格画幅自动等于总画幅 |
| 9:16 主体偏上 | 只在 9:16 时保留为建议：主体别贴底边 |
| P1–P6 / 逻辑补完模式 | 不用；格数 = 实际镜数（≤4），不凑格 |

### 3.3 模板（中文）

```
一张无缝的 2×2 分镜宫格，四个等大的格子拼成一体画面，整体[竖构图 / 横构图]，从左到右、从上到下阅读，没有边框，没有文字。
[挂图时：四格都是附图里的同一个地点——保留它的<结构>和<参照物>。]
[锁定一次：光源方向与色温、空气层、时间——四格共用，只写一次。]
左上：[景别 + 角度 + 这一格的内容/动作阶段]。
右上：[景别（与左上明显跨开）+ 角度 + 内容]。
左下：[景别（与右上明显跨开）+ 角度 + 内容]。
右下：[景别 + 角度 + 内容/余韵]。
每一格都是一个单独的电影镜头。[调色块]。[技术块一句]。四格是同一个地点、同一种光线。
```

### 3.4 要点

- **布局放在第一句写完**（“2×2 四个等大的格子”比“四格”稳；Q60 英文社区原话是“2x2 grid of four equal panels”比“4 panels”稳），逐格按位置描述（Q60 第三方）。
- **锁定条目只写一次，逐格只写变化**；末尾再重复一次“同一个地点、同一种光线”锁定句（Q60 第三方）。
- **一格只干一件事**，不把“走近→拿起→转身”塞进一格。
- 不在画面上要求数字编号：位置用“左上/右上…”说，编号会被画进画面再带进视频（Q60 第三方）。
- 每格之后单独喂 Omni 生成，所以**每格要能独立成为一个好的首帧**（给运动留余地）。
- 宫格出来先过五项再交给剪辑：人/场景/道具/可读性/叙事推进；坏一格就让 Gemini “只改这一格”，不整张重来（Q60 第三方）。这是给 EV 的提示，不写进提示词。

## 四、Omni 视频提示词

### 4.1 通用规则

- **正文中文，以 `meta.stylePrefix`（或该场 `scenes[].stylePrefix`）开头**（build.mjs 校验）。
- **另附英文备用版 `promptEn`**：同一条提示词的英文版，以 `meta.stylePrefixEn` 开头（build.mjs 校验；只有 Omni 能带 `promptEn`）。理由：Omni 官方只评估过英文（EV 11-07）。中英两版内容一一对应，不各写各的。
- **Omni 默认会自己切镜**：单镜头必须写“单镜头，一镜到底，不切镜。”（英文版 `Single continuous shot, no scene cuts.`）；多镜头必须用时间码逐段写，中文写 `0–3 秒：`（长横线），英文版写 `[0-3s]`（build.mjs 校验二者至少其一）。
- **末尾写“以这张图作为视频首帧。”**（英文版 `Use this image as the starting frame.`；Q61 官方三种方法之一，App 里最通用；API 可另用 `<FIRST_FRAME>` 标签）。
- **首帧里已有的东西不再重述**（人物外观、服装、地点陈设），写**运镜 + 主体动作 + 环境变化 + 声音**；人物用“那个男人”“她”泛称（沿用 Veo 官方首帧写法，Omni 文档未明说——推断）。
- **运动要具体**：写清摄影机怎么动、谁在动、环境怎么变；“让它动起来”类模糊说法效果差（Omni 官方）。
- **负面直接写“不要 X / 无 X”**（Omni 官方 `No X.`，和 Veo 相反）：“无对白，无音乐，画面里不要出现文字。”
- **声音关不掉**：首帧档一律写“无对白”，并写出想要的环境音、动作音；要不要音乐明说。
- 表情、细微反应：Omni 手册没专门说，按通用写法（看得见的动作，不写内心）。首帧档本来就只放不说话的镜头，很少用到。
- 不写内部编号，不写 `@imageN`（首帧不是 @ 引用）。

### 4.2 单镜头模板（走法 A、C）

```
prompt：  <stylePrefix>单镜头，一镜到底，不切镜。[景别 + 机位 + 运镜，一句]。[主体/物件怎么动，环境怎么变]。声音：[环境音、动作音]。无对白，无音乐，画面里不要出现文字。以这张图作为视频首帧。
promptEn：<stylePrefixEn> Single continuous shot, no scene cuts. [同上，英文]. Sound: [...]. No dialogue. No music. No on-screen text. Use this image as the starting frame.
```

### 4.3 时间码多镜模板（走法 B）

```
prompt：  <stylePrefix>0–N 秒：[第一镜：和首帧同一构图；运镜 + 动作]。N–M 秒：[第二镜：景别/角度与上一镜明显跨开；运镜 + 动作]。M–10 秒：[第三镜…]。声音：[环境音、动作音]。无对白，无音乐，画面里不要出现文字。以这张图作为视频首帧。
promptEn：<stylePrefixEn> [0-Ns] [...]. [N-Ms] [...]. [M-10s] [...]. Sound: [...]. No dialogue. No music. No on-screen text. Use this image as the starting frame.
```

- 总长 = 10 秒，段与段首尾相接、不重叠；**2–4 镜**，每镜不短于 2 秒。
- 中文时间段用长横线（`0–4 秒`），短横线会被 build.mjs 当成场号组号拦下；英文版 `[0-4s]` 不受影响。
- 第一段必须对得上首帧构图；后面几镜的地点靠前缀和文字维持，要写清是同一地点的哪一部分（必要时点出参照物）。
- 相邻镜头景别跳开，规则同宫格。

## 五、Wan3.0 首帧视频提示词（走法 D：长空镜）

### 5.1 规则

- 时长 **11–30 秒**（Wan 2–30 秒；≤10 秒的归 Omni）。
- **中文写**，以 `meta.stylePrefix`（中文版）开头（build.mjs 校验前缀开头）。
- **紧接着写“生成单镜头，一镜到底，不切镜。”**：Wan 不要求切也会擅自硬切、带叠化鬼影，官方写法是首行声明单镜头（Q61）。build.mjs 对 Wan i2v 也会提示这一句。
- 一镜到底内部可以按时间段写**运动阶段**（推进到哪、看到什么），但要写明是同一镜头里的连续运动；时间段用“0–8 秒”这类**长横线**写（用短横线“8-15”会被 build.mjs 当成内部编号拦下）。
- **不写和首帧矛盾的内容**：Wan 会保护首帧，提示词和首帧冲突时打折执行（Q61 第三方 Atlas）。
- 运动写慢、写少：Wan 大动作偏保守，长镜头越长越容易被合并/切断（Q61 第三方）。
- 末尾写负向清单（Wan 官方格式）：`无台词。无 BGM，只生成环境音和动作音。不要切镜，不要叠化转场，不要画面文字。`
- 渠道里有 `prompt_extend`（智能改写）开关的，**关掉**：它会把写好的切点、时长、朝向重排（Q61 第三方）。
- Wan 出片 **30fps**，其他模型 24fps，剪辑时统一帧率（Q61 推断）。

### 5.2 模板（中文）

```
<stylePrefix> 生成单镜头，一镜到底，不切镜。以首帧为起点：[摄影机怎么动，速度]。0–X 秒：[运动第一阶段，看到什么]；X–Y 秒：[第二阶段]；Y–Z 秒：[收尾，停在什么画面]。[环境怎么变：风、雾、车灯、雨]。音效：[环境音、动作音]。无台词。无 BGM，只生成环境音和动作音。不要切镜，不要叠化转场，不要画面文字。
```

## 六、示例

> 以下全部是**示例**。示例 1 改写自 `tests/fixtures/sample.json` 的 1-1A-G1；示例 2、3 是虚构的组，只为演示写法，不在样张剧情里。
> `frame.refs` 已进数据契约（build.mjs 会核 tag）。

### 示例 1：走法 B（Omni 一次多镜）——1-1A-G1（= sample.json 现行版本）

**判定**：街面空镜，三镜（远景驶来→路缘低角度→侧跟）要切镜；没人说话；总长 10 秒；构图不需要逐镜定死 → B。
**写法**：首帧提示词中文、按 Lira 地点模板的结构写，挂 `@loc_malu_ye` 成图，写进资产参照物（锈蚀路灯杆）；公交车外观、车内乘客剪影未建档，进 `unbuilt`；画幅只写“竖构图”；视频提示词中文正文以全局前缀开头、时间段用长横线、首帧句放末尾；另附英文备用版。
**顺带发现**：这组画的是车外街面，挂在场 1-1A（车厢内）下面；资产盘点里 `@loc_malu_ye` 的 scenes 只登记了 2-1、没有 1-1。两处都是数据问题，交给拆场（01）和副导演核对，不在本文件处理。

```json
{
  "id": "1-1A-G1",
  "scene": "1-1A",
  "model": "omni",
  "craft": "i2v",
  "dur": 10,
  "assets": [
    "@loc_malu_ye"
```
