# 08 LAYOUT 与 Blender

> 管三件事：哪个镜头组要 LAYOUT；分镜表里 `layout.prompt`（给 Blender MCP 的提示词）怎么写；2.5 视频提示词里怎么挂 LAYOUT 产出。
> 对应 JSON 字段：`groups[].layout = { level: "full | static | set", prompt }`，`groups[].refs` 里登记 LAYOUT 产出的 `@videoN` / `@imageN`。
> 证据强度沿用调研文件的标法（强 / 中 / 弱）。“EV 定”= EV 拍板的规则，不再讨论。
> 语言：Blender MCP 提示词和视频提示词都写中文（EV 11-07：所有提示词一律中文）。

## 一、什么镜头要 LAYOUT

### 1.1 定义（EV 定）

- **复杂镜头（暂定）= 需要 LAYOUT 的镜头 → Seedance 2.5 + LAYOUT。**
- **LAYOUT 只管“形”**：多个对象的位置、朝向、路线、先后时序、机位与机位运动、切点。
- **人做什么交给提示词**：LAYOUT 里的人默认是无手脚小人，只表达站位、转身、蹲低、前倾、头朝哪；动作、表情、手上的事一律写在视频提示词里。
- **挂 LAYOUT 视频默认只取位置、路线、机位和时序**，不照搬灰模外观，也不照搬小人的动作（EV 11-07）。
- 人身上的细节动作（脚背勾窗台、撑地趴下、换弹匣）**不上实拍自演，也不靠 LAYOUT**，改设计 / 拆镜（见 04 工艺判定）。

### 1.2 判据（满足任一条 → 要 LAYOUT）

| # | 判据 | 例子 |
|---|---|---|
| 1 | **两个以上会动的对象**，彼此的相对位置、先后次序是戏的一部分 | 三辆车超车拦停公交；追逃里谁先落地、谁从哪边扑上来 |
| 2 | 对象走的**路线 / 方向**必须对（从哪进、往哪拐、倒向哪边） | 柱子往哪倒（HG 39 砍柱子 30 版提示词全在改这个）；气球人从哪栋楼前面飞过 |
| 3 | 一组里**多机位拍同一段动作**，镜头之间的位置和银幕方向要接得上 | 对射：正打 / 反打里双方各躲哪辆车、朝哪边开火 |
| 4 | **机位运动跟着运动物体**，且路径不是一句话能说清的 | 贴车窗从后排滑到前排；跟拍飞行轨迹再上摇 |
| 5 | 文字已经写过、但位置关系**仍很可能被画错**的复杂组合（多排人的前后、多人互相遮挡）；两个人一前一后这种一句话说得清的不算 | PR U23 后排正中，文字写重仍只有约 20% 做对（中） |

### 1.3 反例（不要 LAYOUT）

| 情况 | 去向 | 理由 |
|---|---|---|
| 单人或两人对白、站着 / 坐着说话 | SD2.0 文戏 | 位置一句话说得清，LAYOUT 不加分 |
| 人身上的细节动作（手、脚、接触点） | 改设计 / 拆镜 | 灰模管不到；网友定性一致：“blocking 锁构图，丢接触点”（Q54，弱） |
| 物件的形状和状态（弹壳、碎裂、钱砖） | 道具参考图 + 拆特写（Wan3.0 / 2.5） | LAYOUT 不管外观和物理细节 |
| 空镜、静态物件特写 | 首帧档（Omni） | 没有关系线 |
| 群演只做背景、没有路线要求 | H3 / 文字 | 一句“路人来回走”就够 |
| **人群整体的简单动线**（四散逃跑、涌向某处、围上来），每个人具体怎么跑不重要 | 文字（主角不说话 → H3；主角说话 → SD2.0） | EV 11-07：交给视频模型效果更好；LAYOUT 里手 K 的群众路线和节奏太整齐，反而假。只有关键人物之间的位置、先后关系**复杂到文字容易画错**时，才把那几个关键人放进 LAYOUT，群众不进；两个人一前一后站着这种一句话说得清的，不算（EV 11-07） |
| 单个对象一条直线（一辆车从左开到右） | 文字 | 一句话不会歧义 |
| 表情、情绪、表演强度 | 文字（07 表演与声音） | PR 的表演全写在文字里（Q55，中） |

> 拿不准时问一句：**这组如果只写文字，最可能被画错的是什么？** 答案是“位置 / 方向 / 先后 / 机位”→ LAYOUT；答案是“动作做得不像 / 东西长得不对”→ 不是 LAYOUT 的活。把这句判断写进 `reason`。

## 二、三档 LAYOUT

### 2.1 定义与产出物

| 档 | `level` | 搭什么 | 动不动 | 产出物（交给用户 / 挂进 2.5） |
|---|---|---|---|---|
| **完整 LAYOUT** | `full` | 场景灰模 + 角色 / 车辆替身 + 每个 Shot 一台摄像机 | 替身按时间轴动；机位可动；用时间轴标记（Marker）绑定摄像机自动切镜 | ① **预演视频** 1 条（时长 = 组时长，切点 = Shot 分段，无音轨）→ 挂 `@videoN`；② 每个 Shot 的首帧截图；③ 俯视总图 1 张（带时间轴各时刻位置）→ 自查用 |
| **静态站位 + 机位** | `static` | 场景灰模 + 替身摆在关键时刻的位置 + 每个 Shot 一台摄像机 | 替身不动（每个 Shot 可以摆一次，不做中间过程）；机位最多起止两个关键帧 | ① 每个 Shot 从摄像机出 1 张**站位图** → 挂 `@imageN`；② 俯视总图 1 张；③ 若某个 Shot 有机位运动，额外出一段“替身不动、只有机位动”的短视频 → 可挂 `@videoN` |
| **只搭场景** | `set` | 只有不会动的场景灰模（地面、墙、车道、掩体、门窗），按真实尺寸 | 全不动；不放替身，不定机位 | ① 俯视总图 1 张；② 2–3 张人眼高度的空间截图（标注方位）→ **默认不挂进 2.5**，给用户核对空间、写方位词、或给 Gemini 出场景图当构图依据 |

### 2.1之二 场级站位锚（EV 11-09）

每一场都有平面图 `scenes[].blocking`（03 第四节之三，只是页面上的俯视示意，不进 Blender）。`static` 也可以挂在**场**上，而不是某一个镜头组：同一阵型跨几个镜头组出现时，把那张平面图标 `anchor: true`，照它搭一次静态站位，每个用到它的 Shot 一台机位、出一张站位图，各组挂自己那张。场景和替身只搭一次，机位按组加。页面在场头显示俯视图（机位扇形标着“G3·1”这样的组号和镜头号）和这段 Blender 提示词。站位锚不改模型档位。

### 2.2 怎么选（写分镜表时定计划档）

1. 判据 1、2、4 命中（有运动关系或运动机位）→ `full`。
2. 只命中判据 3、5（位置 / 遮挡 / 多机位要接上，但对象在这一组里基本不动或只是一个落位）→ `static`。
3. 空间本身复杂（掩体、门洞、楼层），镜头里的人和物关系文字写得清 → `set`。
4. 同一场的几组共用一个空间：**场景只搭一次**，后面的组在同一个 .blend 里另存版本、加替身和机位，不重搭。

### 2.3 退档规则（用户的 Agent 执行时做不到就退）

- **只往下退，不自动升档。** 计划档写在 `level`，实际交付档由用户的 Agent 在完工报告里写明。
- `full → static`：出现任一情况就退
  - 替身动画两轮自查后仍有穿模、路线反向、先后顺序不对；
  - 当前 MCP / Blender 渲染不出动画视频（只能截图）；
  - 用户说时间不够。
- `static → set`：摄像机两轮调整后仍拍不清关键关系（前后排、谁挡谁），或替身尺寸 / 朝向无法确认。
- `set` 也做不出（MCP 连不上、建不了物体）→ **不做 LAYOUT**，这组改成“2.5 纯文字”，方位关系全部写进文字；同时回看能不能改设计 / 拆镜，把关系拆进几个简单镜头。
- 退档后**视频提示词要换挂法**：按第四节 4.4 的替换句改，别把 `@video1` 的句子留着。
- 每档的 Blender 提示词末尾都要带“做不到就退档”的条款（模板里已写），让对方 Agent 自己判断，不要硬做。

## 三、给 Blender MCP 的提示词模板

### 3.1 通用约定（三档共用，每条提示词都要原样带上“通用约定”段）

- **单位**：1 Blender 单位 = 1 米；Z 轴朝上，地面 Z = 0。
- **坐标**：世界原点放在场景的一个明确地标上（写清是哪里）；主要运动方向沿 **+Y**；画面左右用“+X = 主运动方向的右手边”。
- **正面朝向**：所有替身建模时正面朝 **-Y**（和 Blender 前视图、自带的 LAYOUT 小人库一致），摆放时再绕 Z 轴转到需要的朝向；**每个替身正面贴一块橙色小方块**标正面（人：头前、胸前各一块；车：车头一块）。
- **命名**：集合 `SET`（场景）、`ACTORS`（人）、`VEHICLES` / `PROPS`（车、道具）、`CAMS`（摄像机）；物体 `SET_路面`、`CHAR_<角色名>`、`VEH_<名>_1`、`PROP_<名>`、`CAM_SH01`、`CAM_SH02`…；时间轴标记 `SH01`、`SH02`…；俯视自查机位 `CAM_TOP`（不进预演）。
- **替身**：
  - 有库就用库：本 Skill 自带小人库 `assets/blender/LAYOUT小人.blend`（集合 `LAYOUT_小人_无手脚` / `LAYOUT_小人_有手脚`，正面朝 -Y，头和胸各一块橙色块 = 正面）。把这个文件的绝对路径写进提示词，让智能体用 `bpy.data.libraries.load(路径)` 追加集合 `LAYOUT_小人_无手脚`；也可以在 Blender 偏好设置 → 文件路径 → 资产库里登记它所在的文件夹，从资产浏览器拖进场景。改色前先“设为单用户”（材质 `LAYOUT_身体`），否则几个人一起变色。
  - 没库就用基本体现搭“无手脚小人”：圆锥身体（底半径 0.25 m、顶半径 0.08 m、高 = 身高 × 0.87，底在 Z=0）+ 球头（半径 0.11 m，顶到身高）；原点放在脚底中心；正面贴橙色块。
  - **不要手脚、不要绑骨动作**：绑骨动作会被视频模型照抄成僵硬动作、出现冻腿滑步。人的动作只用这几种：整体平移、绕 Z 转身、身体绕脚底前倾、身体 Z 向缩放表示蹲低、头转向。
  - **角色不能只靠颜色区分**：两个以上角色同时出现时，除了身体颜色不同，再加一个剪影特征（高矮差、身体粗细、头顶一个圆柱当帽子、肩上一块板当披风等），写清哪个特征对应谁。
  - 车辆 / 大道具：长方体按真实尺寸（车身 + 一个小一号的驾驶室方块就够），车头贴橙色块。
- **外观**：纯灰白模，不要贴图、不要材质细节、不要灯光设计；颜色只用视口“物体颜色”（Object Color）区分对象（改色时同时改 `ob.color`）。理由：带贴图的预演容易被模型当成平面画面照搬（blender-shot-video 的论点，弱）。
- **动画**：帧率 24 fps；总帧数 = 组时长 × 24（10 秒 = 240 帧，第 1 帧开始）；**手 K 关键帧，不用刚体 / 物理模拟**（模拟每次结果不同，方向控制不住）；速度给成 m/s 并核对距离（例：30 km/h ≈ 8.3 m/s）。
- **机位**：每个 Shot 一台摄像机 `CAM_SH0N`，写明位置（米）、朝向（看向哪个物体或方向）、焦距（mm，按 36 mm 全画幅）、离地高度；机位运动只用关键帧或“跟踪到”约束；**机位别贴太近**——PR 片方自述机位太近模型读不懂，拉远后下一条就成了（Q54，弱）；关键关系（前后、遮挡）必须在这台摄像机里看得出来。
- **切镜（EV 11-07 定）**：多机位**剪成一条视频**，不是每个机位各出一条。同一条时间轴把整段动作从头演到尾，用 Marker `SH01/SH02…` 绑定对应摄像机（Bind Camera to Markers）按时间轴自动切；切点 = 视频提示词里 Shot01、Shot02、Shot03 的分段。
- **出图出片**：从**场景摄像机**渲染，不要拿视口截图当成片（视口焦距和摄像机焦距不是一回事，EV 踩过：视口 85 mm ≈ 摄像机 42.5 mm）。渲染引擎 Workbench、光照 Flat、颜色 = Object、背景中灰；关掉网格、名字、辅助线叠加；画幅按分镜本 `meta.aspect`，**短边 720**（9:16 = 720×1280，16:9 = 1280×720；EV 11-07 定）；MP4（H.264）、**不带音轨**（带音轨的预演会把声音带进生成，Q53 U23，强）。
- **存放**：所有产出放在当前 .blend 同目录的 `LAYOUT/` 文件夹；文件名 `<组号>_layout.mp4`、`<组号>_SH01.png`、`<组号>_top.png`；.blend 另存为递增版本（`<组号>_v001.blend`、`_v002`…），不覆盖。
- **自查**：做完从每台摄像机看首帧、中间帧、末帧，再从 `CAM_TOP` 俯视看一遍，确认位置、方向、先后都对；最后用一张表报告每个对象在关键帧的位置和朝向，以及实际交付的是哪一档。

## 四、2.5 视频提示词里怎么挂 LAYOUT

### 4.1 结构（按这个顺序写）

1. **全局风格前缀**（meta.stylePrefix）。
2. **素材清单放最前**：每个 `@imageN / @videoN` 一行，写它是什么、管什么、不管什么。PR 带预演的提示词 90% 在前 15% 就讲清视频干什么（Q55，中）；2.5 官方手册也是“素材指代”放最前。
3. **权限条款**（LAYOUT 视频管什么、不管什么）。
4. **替身条款**（每个色块 / 形状对应谁；色块不是实物；灰模不会出现在成片里）。
5. **场景条款**（场景图替换灰模背景，只管外观不管构图和运动）。
6. **覆盖条款**（文字和 LAYOUT 不一致的地方，明说以文字为准）。
7. **Shot01；Shot02；…**：**每一段要发生什么仍然写成文字**，人的动作和表情写在这里。
8. 声音（环境音、台词）。LAYOUT 视频没有音轨，声音全靠文字。

### 4.2 权限条款：管什么 / 不管什么

| LAYOUT 视频管 | LAYOUT 视频不管 |
|---|---|
| 对象在画面里的位置、朝向、路线 | 外观、颜色、材质、灰模质感 |
| 先后顺序、出场时机 | 光线、色调、天气 |
| 机位、景别、机位运动 | 人的动作细节、表情、表演 |
| 切点（与 Shot 分段一致） | 声音 |

默认句（中文，我们的写法；EV 11-07 定默认只取位置、路线、机位和时序）：
> `@video1 是灰模预演：只参考其中<对象>的位置、路线、先后顺序、摄影机位置与运动，以及切点；不参考它的灰色外观、颜色和光线，也不参考小人的动作。`

灰模里没有人时，最后半句可以省。

权重三种写法，按需要选（PR 原句，Q52/Q55）：
- **整段照搬**（结构必须一比一）：“THE PREVIZ IS PRESERVED EXACTLY: every camera position, every cut, every figure movement … copied 1:1 … Only the appearance changes.”（U12）→ PR 这类切点对上约 76%（Q49，中）。
- **只取机位、节奏、位置**（我们的默认，EV 11-07 定）：“controls CAMERA and RHYTHM only: match its per-shot camera framing, movement, shot order, pacing and the screen positions of its blockout figures”（U1）；“copy its camera placements, pacing and the positions of the pink figure (the girl), the purple figure (the driver) and the yellow car. IGNORE its low-poly placeholder look.”（U23）
- **部分参考**（文字为主）：“<<<video_2>>> 只作约40%的参考：机位高度、与车队的侧距、构图与超越的节奏——晃动的力度、四拍表演与前景树影的密度以本文字为准”（U15）。
- 外观隔离最硬的写法：“<<<video_1>>> controls MOTION ONLY … It contributes NOTHING to the visual style. <<<image_1>>> and <<<image_2>>> control APPEARANCE ONLY … These roles never cross.”（U38）

### 4.3 替身条款与场景条款

- **色块 → 角色映射**（PR 44% 的预演提示词这样写，Q55）：
  - “YELLOW figure = the heroine”（U1）
  - “<<<video_2>>> — the heroine, REPLACES the yellow figure … She takes the yellow figure's exact position, motion and timing from the video.”（U12）
  - “Replaces the PINK cube in <<<video_1>>>.”（气球段）
  - 中文写法：`@image2 是童嘉许，替换灰模里的蓝色小人，占它的位置、朝向和走位。`
- **替身只标位置**：`灰模里的形状只表示位置、身高和朝向，不是角色的样子。`
- **色块不是实物**（防止被画成道具）：`小人头前、胸前的橙色小块只表示正面朝向，不是实物，不要画出来。`
- **灰模不出现在成片**：PR 原句 “The blockout figures never appear in the final render — they exist only as placement guides.”
- **场景替换**：PR 原句 “<<<image_3>>> — the environment, REPLACES the previz background … The previz's layout is kept … but every material becomes this city's look. Controls architecture, materials, palette and atmosphere only, not framing and not motion.”（U12）
  中文：`@image1 是<地点>，替换灰模里的场景：保留灰模的布局，所有外观按 @image1；它只管建筑、材质、色调和氛围，不管构图和运动。`
- **覆盖条款**：PR 原句 “THREE OVERRIDES to the layout: (1) there is NO cut when the falling log passes the lens … (2) … MIRRORED to sit BEHIND the taxi … (3) …”（U23 sc17）。中文：`与预演不同的地方以文字为准：① … ② …`

### 4.4 每档的挂法（退档时照此替换）

| 档 | refs 登记 | 视频提示词里的那一句 |
|---|---|---|
| `full` | `@videoN` = 预演视频（多机位按时间轴剪成的一条） | `@video1 是灰模预演（<N> 秒，<k> 段 <k-1> 次硬切）：只参考……（4.2 默认句）。剪切点与 @video1 的分段一致。` |
| `static` | 每个 Shot 的站位图各占一个 `@imageN`（多 Shot 时也可只挂最关键的一张）；有机位运动视频的另挂 `@videoN` | `@image3 是 Shot01 的灰模站位图：只参考人物和车辆在画面里的位置、朝向和机位构图，不参考它的灰色外观；运动过程按文字。` 有机位视频时加：`@video1 的替身是静止的，只参考摄影机运动，人和车怎么动按文字。`（PR 静态预演原句：“The layout is STATIC — IGNORE its low-poly placeholder look; it controls layout only, never style.”） |
| `set` | 默认不挂 | 把截图里看到的空间关系翻成方位词写进文字（“光头躲在大门一侧那辆车的车尾后，敌人躲在里侧那辆车的车头左角”）。 |
| 不做 | — | 同 `set`，所有位置、方向、先后都写成文字，再考虑拆镜。 |

### 4.5 几条硬规矩（来自 PR 实证）

- **挂了预演也要把每段写成文字。** 预演里某一段画不画、画成什么，主要看文字有没有写：U31、U22 v5 写了 → 几乎全照做；U22 v1–4、v6 没写 → 基本不照做（Q53，中）。
- **预演看不出的关系，文字说了也常做错**：U23 预演是正面低机位，前后排看不出，文字写“后排正中”仍只有约 20% 做对（Q53，中）。→ 关系要靠选机位让 LAYOUT 自己看得出。
- **预演时长和组时长尽量相等**；不等时写明按比例拉伸（PR：“copied from <<<video_1>>> and retimed proportionally to 15.0 s total (the video runs 7 s)”，U12）。
- **表演写在文字里**：PR 低模那套，视频只给机位、节奏、位置，表情 / 情绪另写成段（37% 有专门段，Q55，中）。
- 2.5 能跟住的是“时间轴上的东西”（切点、节奏、构图），跟不住的是接触点、具体动作、站位细节（Q54，弱～中）——别指望 LAYOUT 解决动作。

### 7.2 资料冲突 / 待裁定

1. **一组多 Shot 时 LAYOUT 出一条剪好的片，还是每个机位各出一条？** 样张原写“Camera_A / Camera_B 两段，二选一挂”；HG 砍柱子方案和 PR 都是 Marker 切成一条、切点写进提示词。**EV 11-07 已裁定：多机位剪成一条视频，按时间轴切，对上提示词里的 Shot01–03。**
2. **跑动的人用不用带动作的人偶？** HG 砍柱子方案（11-03）说武僧跑步“胶囊体只走位置，V2V 读到的人体动作会很弱，不推荐”，建议 Mixamo 跑步循环；EV 11-05 定“默认无手脚小人”。本文件按 EV 11-05 写（无手脚、动作交给文字）。群体奔跑这类是否例外？
3. **剪影特征 vs 小人库只靠颜色区分。** 记忆里的调研结论是“不能只靠颜色区分，要加剪影特征”；EV 的 LAYOUT 小人库区分角色的方法是改身体颜色，PR 也主要靠色块映射（44%）。本文件要求“颜色 + 一个剪影特征”，要不要给小人库补几个剪影配件（帽子 / 高矮 / 粗细）？
4. **2.5 手册“素材够准时只指代、不复述” vs Q53“文字没写的段落基本不照做”。** 本文件按 Q53 写：挂了预演也逐段写文字。手册口径是否另作说明？
5. **预演分辨率。** 样张写 640×1138（视口预览）；HG 方案写 854×480（对齐 480p 输出）。**EV 11-07 已裁定：短边 720**（Workbench 从摄像机渲染、不用视口预览）。
6. **`set` 档截图挂不挂进 2.5？** 本文件默认不挂（怕和 `@loc` 场景图抢构图）；也可以挂成“只参考空间布局”。待定。
7. **退档后的视频提示词放哪？** 现在 JSON 只有计划档的一份提示词，退档靠用户按 4.4 自己替换。要不要在 `layout` 里加一个 `fallbackPrompt` 字段，表里直接给替换段？（影响 build.mjs 和模板）
8. **权重默认值。** PR 三种写法并存（整段照搬 / 只取机位节奏位置 / 约 40%）；PR“整段照搬”的切点对上率更高（76% vs 按切点时间写 40%，口径不同）。**EV 11-07 已裁定：默认只取位置、路线、机位和时序，不照搬灰模外观和人的动作。**
9. **Blender MCP 实际能做到哪档还没摸底**（执行计划 P0.6）。三档的产出物和退档条件是按 EV 本机经验推的，摸底后可能要改“退档触发条件”。

## 八、实测记录（2026-11-07，《归来凤栖处》1-1-G6，Blender 5.1.2 + MCP for Blender，一轮会话）

- **结果：完整 LAYOUT（full）一轮做成**——17 个替身（库里的无手脚小人）、场景灰模、240 帧动画、三机位按 Marker 切镜，导出 720×1280 / 24fps / H.264 / 10 秒一条视频 + 三张 Shot 首帧 + 四张俯视。渲染 6 秒。文件在 `work\layout\1-1-G6\`。
- **照提示词原样做会出的问题（写提示词时要避开）**：
  1. **机位被前景人物挡住**：SH01 摄像机放在太监身后同高度，第一帧整个被太监挡住；太监后退路线还穿过机位。→ 写机位时先确认摄像机和镜头前 3 米内没有替身、替身路线不穿过机位；或直接写“摄像机高于前景人物头顶 1.5 米以上”。
  2. **竖屏下焦距按横屏习惯写太紧**：9:16 时水平视角窄，50mm“双人中景”两个人都被画框切掉一半。→ 竖屏双人镜头写 28–35mm，或把机位拉远。
  3. **“画面下沿刚好切掉某人”这类精确构图两轮没调准**（沈云卿仍露在 SH01 底部中间）。→ 构图要求写成可检查的条件（“某人不在画面内”），并允许 Agent 自己移机位。
- **Blender 5.x 的坑（提示词里不用写，执行的 Agent 要知道）**：动作数据是分层的（`action.layers → strips → channelbags → fcurves`，没有 `action.fcurves`）；导出视频要先设 `image_settings.media_type='VIDEO'` 再设 `FFMPEG`；有 Marker 绑定摄像机时，渲染俯视图要先临时解绑，否则仍用 Marker 的摄像机。
