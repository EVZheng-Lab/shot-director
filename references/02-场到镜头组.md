# 02 场 → 镜头组

> 来源：官方 higgsfield-shotlist-director（Prompt density / 复杂度预算）；AIMV storyboard-designer（拆分规则，去掉 MV 前提）；15 期 Q59、Q60、Q61；EV 11-06 拍板。

## 一、定义

**镜头组 = 一次生成 = 分镜表一行。** 一场通常不止 15–30 秒，拆成几个镜头组来演。镜头写在视频提示词里（Shot01、Shot02…），不单独成行。
**例外**：首帧生视频档一行 = 一张首帧 = 一次生成；Omni 一次出多镜时，一行里用时间码写几个镜头。

## 二、合并：下面**全部**满足才放进同一组

1. 同一批人在画面里
2. 同一地点（或同一地点的局部）
3. 一个连续的情绪/时间单元：没有时间跳跃
4. **同一工艺、同一模型**（见 04）——工艺不同就拆
5. 在所选模型的单次时长内演得完（见第四节）

## 三、拆开：下面**任一**发生就另起一组

1. 地点切换（车厢内 → 车外路面）
2. 重要角色进出，挂载的角色图要变
3. 工艺或模型变了（主角对白 SD2.0 → 群演喊话 H3 → 多车调度 2.5+LAYOUT）
4. 一段需要单独时长的表演弧：一个反应要 5–7 拍才建立起来，不和动作挤一组。**但不拆碎崩溃**：一次连续的情绪崩塌是一组，即使剧本写成三行
5. 插入/切出到道具或屏幕的特写，且该特写工艺不同（例：有物理过程的物件特写 → Wan3.0）

**复杂度预算**（超了就该拆）：强动作 > 2 个 · 运镜 > 2 种 · 重要角色 > 3 人 · 复杂特效事件 > 1 个 · 地点变化 > 1 次。

拿不准时**宁可多拆、每组短一点**——模型处理紧凑的组比塞满的组稳。

## 四、时长

| 模型 | 单次范围 | 说明 |
|---|---|---|
| SD2.0 | 4–15 秒 | |
| SD2.5 | 4–30 秒 | 一组可以比 2.0 长一倍，但一条里切点越多越差（Q57） |
| H3 | 4–15 秒 | |
| Wan3.0 | 2–30 秒 | |
| Omni | 填 10 秒 | EV：单次固定 10 秒；短于 10 秒的空镜照用 Omni，后期裁 |

- 时长阶梯：4–8 秒 = 一个强动作；8–12 秒 = 一个动作 + 一次揭示；12–15 秒 = 2–3 个简单节拍。
- **有台词的组按字数估时**：中文约 4.5 字/秒，再加 2 秒反应与停顿（火宝短剧的估时公式，Q59）。角色档案 voice 里写了语速偏慢 / 偏快的，按 3.5 / 5.5 字/秒估。估出来超上限就拆。
- **一句长台词装不进一组**：可以从句中自然停顿处拆到相邻两组。`lines` 里后半句加 `"cont": true`，前后两半照原文逐字切开（脚本会把它们拼回去核对）。
- **不为凑满时长注水**：节拍只够 6 秒就写 6 秒（Omni 除外）。
- 表里填**生成时长**，不填剪辑取用时长——取多少、加减速是剪辑师看到成品后的二创（EV 11-06）。

## 五、组号与顺序

- 组号 = 场号 + `-G` + 序号：`1-1A-G1`、`1-1A-G2`。
- 按剧情顺序排；剧本台词按原顺序落在各组 `lines` 里（脚本会按顺序逐句核对，漏一句、顺序错都会报）。
- 每组写 `reason`（派活理由）：一句话说“是什么镜头 → 为什么是这个工艺/模型”。

## 六、和 AIMV 原规则的差异（改过的地方）

- AIMV 偏好“用满 15 秒、做大事件”（理由：同一次生成内一致性最好）。我们改为：**工艺不同就拆**，时长跟节拍走。按难度派活是这个 Skill 的主线，组太大就没法派。
- AIMV 是 MV（无对白）前提，会主动过滤文学细节。我们是有对白的剧，**台词一句不能丢**。
